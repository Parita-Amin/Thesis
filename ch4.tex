\section{Querying Survey Ontology in Protégé}
\label{sec:queryingontology}

The ontology vocabularies can be queried using query languages like 
DL query\footnote{https://protegewiki.stanford.edu/wiki/DL\_Query} 
and \ac{sparql}. 
Protégé offers a plugin for DL as well as SPARQL queries which are discussed in this section. 

\subsection{DL Query}
\label{subsec:dlquery}

Vasilevsky\footnote{https://ontology101tutorial.readthedocs.io/en/latest/EXERCISE\_BasicDL\_Queries.html} 
defines DL query as a class expression that is constructed using constructs such as 
`and’, `or’ (corresponding to set intersection) and `some’. 
Users can rapidly check that class definitions encompass the right subclasses 
by running them via the DL Query tab. 

Alternately, 
one can examine arbitrary descriptions 
for class membership without having to build 
placeholders for specified classes. 
The DL Query tab can be opened using Tabs option under Windows menu. 
It is important to configure a reasoner to successfully express a DL query.
Figure~\ref{survey-dl-query} 
shows expression of a sample DL query using the survey ontology in protégé. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-dl-query.png}
    \caption{DL Query on Survey Ontology}
    \label{survey-dl-query}
\end{figure}

\subsection{SPARQL Query}
\label{subsec:sparql}

According to \ac{w3c}~\cite{garlik2013sparql}, 
\ac{sparql} queries use 
conjunctions, disjunctions, aggregation, subqueries, negation, and other operations 
to define queries and optional graph patterns. 
Protégé offers plugins for 
``\ac{sparql} Query'' and ``Snap \ac{sparql} Query''.

\subsubsection{Using \ac{sparql} Query Plugin}
\label{subsubsec:usingsparql}
    
\ac{sparql} plugin in protégé is used to express simple queries on ontologies like displaying classes and subclasses. 
For instance, 
consider the following query:

\begin{lstlisting}

    SELECT * WHERE { ?Respondent 
        survey:hasOEAnswer_LikeBest ?Answer_LikeBest
	OPTIONAL { ?Respondent 
	survey:hasOEAnswer_Strengths ?Answer_Strengths }
    }

\end{lstlisting}
       
 Figure~\ref{survey-sparql-query} 
 shows the result of expression of \ac{sparql} query on survey ontology. 
 Here, 
 the query is used to display 
 ``Respondent'',  ``hasOEAnswer\_LikeBest'',  and ``hasOEAnswer\_Strengths'' 
 with column titles Respondent, Answer\_LikeBest and Answer\_Strengths respectively.
    
\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-sparql-query.png}
    \caption{SPARQL Query on Survey Ontology}
    \label{survey-sparql-query}
\end{figure}
    
\subsubsection{Using Snap \ac{sparql} Query Plugin}
\label{subsubsec:usingsnapsparql}

The Snap \ac{sparql} plugin in protégé 
is generally used to express comparatively complex queries 
on ontologies 
like displaying description of individuals. 
For instance, 
consider the following query:    

\begin{lstlisting}

    SELECT * WHERE { ?Respondent rdf:type survey:Respondent .
	OPTIONAL {?Respondent survey:hasLikertQ6Ans 
		?The_instructor_clearly_answers_questions}
    } ORDER BY ?Respondent 
   
\end{lstlisting}

Figure~\ref{survey-snap-sparql-query} 
shows the result of expression of Snap \ac{sparql} query on survey ontology. 
It is necessary to enable a reasoner for successful working of Snap \ac{sparql} query. 
Here, 
the query is used to display 
``Respondent'' and ``hasLikertQ6Ans'' 
with column titles ?Respondent and ?The\_instructor\_clearly\_answers\_questions respectively.
 
\begin{figure}[htp]

\subsection{Representation of Survey Ontology in OntoGraf}
\label{subsec:surveyontograf}

To start with the graph formation, 
the classes 
``owl:Thing'', 
``Survey'', 
``SurveyResponse'', 
``SurveyQuestions'', 
``SurveyAnswers'', 
``Respondent'', and 
``SurveyCollection'' 
were selected followed by their expansion by double-clicking them. 
This expansion adds all the classes that are connected to the classes. 
The classes connected includes both the subclasses as well as the ones linked through the object properties and individuals. 

Figure~\ref{ontograf} 
shows the graph generated using OntoGraf for survey ontology. 
Solid blue lines in the graph are used to denote the relationships between the classes and their subclasses whereas dashed lines are used to represent the object properties. 
``Arc Types'' 
represent symbols for different object properties. 
The classes are denoted by yellow solid dot followed by the class name where as individuals are denoted by purple solid diamond followed by the instance name.
