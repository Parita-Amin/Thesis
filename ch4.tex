\label{subsec:surveyclasses}

All the classes can be created and 
described using the steps described in Section~\ref{subsubsec:classhierarchy}. 
The resultant class hierarchy for the survey ontology 
%would be as

A {\tt Survey} can have

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-class-hierarchy.png}
    \caption{Class Hierarchy in Survey Ontology}
    \label{survey-class-hierarchy}

The {\tt SurveyCollection} class corresponds to a particular collection of survey responses
for a particular course offering ({\tt CourseOffering} class). 
The type of survey used is feedback survey ({\tt FeedbackSurvey} class, subclass of {\tt Survey})
with Hepting's feedback survey 
as the specific survey instrument.
%({\tt HeptingStudentFeedbackSurvey} class)
%and responses to the survey ({\tt HeptingStudentFeedbackSurveyRespondent} class). 

The survey questions and survey answers have classes 
corresponding to various forms of question-answer. 
Generally, 
feedback surveys consist of two types of questions, 
namely, 
\emph{Likert Questions} and \emph{Open-ended Questions}.
The type of questions might differ depending on the designer of the survey.
The feedback survey in this research has Likert and Open-ended questions. 
The classes described for the question and answer are 
{\tt SurveyQuestion} and {\tt SurveyAnswer} 
as sub-classes of 
{\tt HeptingStudentFeedbackSurvey} and 
{\tt HeptingStudentFeedbackSurveyRespondent} 
respectively.
For each survey question, 
there is an answer, 
where both of them are considered as distinct classes. 
The details of {\tt SurveyQuestion} and {\tt SurveyAnswer} classes 
are in following sections. 

\subsubsection{The ``SurveyQuestion'' Class}
\label{subsubsec:surveyqueclass}

Figure~\ref{survey-que-class} shows the {\tt SurveyQuestion} Class from survey ontology. 
Each question in survey has one question label whose datatype is string. 
It has two sub-classes, one for each of the 
{\tt OpenEndedQuestion} and {\tt LikertScaleQuestion} classes. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-que-class.png}
    \caption{{\tt SurveyQuestion} Class in Survey Ontology}
    \label{survey-que-class}
\end{figure}

The {\tt OpenEndedQuestion} class describes 
the set of 3 open-ended questions on the survey instrument,
where each question has its own class, %(sub-class of {\tt OpenEndedQuestion}), 
namely, 
{\tt OEQ1}, {\tt OEQ2}, and {\tt OEQ3},
which correspond to questions:
%with question labels, 
``What do you like best about the course?'', 
``What would you like to change about the course?'', and 
``What do you think the instructor's greatest strengths are?''. 

Likert-scale questions are the questions for which 
the answers are from the preset list of answers. 
The {\tt LikertScaleQuestion} class represents 
a set of 9 Likert-scale questions from the survey instrument.
Each Likert-scale question has a {\tt LikertQuestion} and a {\tt LikertScale}.  
where {\tt LikertQuestion} has the 9 questions each as a distinct class. 
{\tt LSQ1}, {\tt LSQ2}, . . , and {\tt LSQ9} are the classes 
with question label representing the question.

The {\tt LikertScale} class describes the Likert scale used by Hepting in his survey. 
The Likert scale has degrees of agreement -- either in the form of label or a number, 
which determine the type of Likert-scale used. 
Here, there are 5 options, 1, 2, 3, 4, and 5  
where 1 = Never and 5 = Always (see Figure~\ref{feedback-form}).
In the vocabulary, each of these degrees of agreement 
has been described as an individual of the {\tt LikertScale} class 
as shown in Figure~\ref{likert-scale-class}. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/likert-scale-class.png}
    \caption{{\tt LikertScale} Class in Survey Ontology}
    \label{likert-scale-class}
\end{figure}

\subsubsection{The ``SurveyAnswer'' Class}
\label{subsubsec:surveyansclass}

The {\tt SurveyAnswer} class represents the responses to the questions of the survey. 
It has two sub-classes, one for each of the 
{\tt OpenEndedAnswer} and {\tt LikertScaleAnswer} classes.

The {\tt OpenEndedAnswer} class represents 
the answers for the 3 open-ended questions.
Open-ended questions have unpredictable answers. 
The answer to each question is described by a distinct class (sub-class of {\tt OpenEndedAnswer},
namely, 
{\tt OEQ1Ans}, {\tt OEQ2Ans}, and {\tt OEQ3Ans}) 
that consists of a string.
   
The {\tt LikertScaleAnswer} class represents 
the set of answers for each of the 9 Likert-scale questions. 
There are 9 sub-classes of the {\tt LikertScaleAnswer} class, 
namely, 
{\tt LSQ1Ans}, {\tt LSQ2Ans}, . . . , and {\tt LSQ9Ans}.
The answer to each of these questions is a value belonging to
the {\tt LikertScale},
which is between 1 and 5.
In case of no answer, the data field will be left blank. 
The next step is to describe properties.

\section{Data Validation Using SHACL}
\label{sec:shacl}

\ac{shacl}4P is a Protégé plugin for \ac{shacl}, 
which uses \emph{shapes} to describe constraints. 
\ac{shacl} can be used to validate the data 
which are stored in spreadsheets. 
For the feedback survey, 
the Likert answers can only have values 
1, 2, 3, 4, 5, or No Answer (blank cell). 
To restrict the values of data properties 
corresponding to Likert questions 
in Table~\ref{survey-data-properties-domains-and-ranges}, 
\ac{shacl}4P has been used. 

Protégé offers views for the \ac{shacl} editor as well as \ac{shacl} constraint violations. 
A reasoner should be enabled to get the best results from \ac{shacl}4P.
 
The \ac{shacl} editor provides three buttons, 
namely, 
{\tt Open}, 
{\tt Save}, and 
{\tt Validate}. 
After opening the shapes file ({\tt Open} button), 
changes can be made and saved ({\tt Save} button). 
Where as the {\tt Validate} button allows users to validate the data.

\section{Querying Survey Ontology in Protégé}
\label{sec:queryingontology}

The ontology vocabularies can be queried using query languages like 
DL query\footnote{https://protegewiki.stanford.edu/wiki/DL\_Query} 
and \ac{sparql}. 
Protégé offers plugins for DL and SPARQL queries, which are discussed in this Section. 

\subsection{DL Query}
\label{subsec:dlquery}

In her tutorial,
Vasilevsky\footnote{https://ontology101tutorial.readthedocs.io/en/latest/EXERCISE\_BasicDL\_Queries.html} 
defines DL query as a class expression that is constructed with 
{\tt and}, {\tt or},  and {\tt some}. 
Users can rapidly check that class definitions encompass the proper subclasses 
by running them via the DL Query tab. 

Alternately, 
one can examine arbitrary descriptions 
for class membership without having to build 
placeholders for specified classes. 
The DL Query tab can be opened using Tabs option under Windows menu. 
It is important to configure a reasoner to successfully express a DL query.
Figure~\ref{survey-dl-query} 
shows expression of a sample DL query using the Survey Ontology in Protégé.

\subsubsection{Describing Fields in Terms of Linked Data}
\label{subsubsec:describingfields}

The next step is describing the CSV data
in terms of linked open vocabularies.

allows using vocabularies described in the list of ontologies.

The vocabulary can be selected for each field of the CSV 
to represent the data. 

For instance, 
{\tt survey:hasLSQ1Ans}
property can be assigned to the data corresponding to the field, 
\emph{Q01\_Rate instructor->1. The instructor is well-prepared for class} 
of the CSV.

\section{Publishing Survey Vocabulary with License}
\label{sec:publishingsurveyvocabulary}

As mentioned in Section~\ref{sec:announcinglod}, 
it is necessary to specify an appropriate license for linked open data. 
When there is a clear declaration regarding 
the source, ownership, and conditions associated to 
the use of the public data, 
data reuse is more likely to happen.
