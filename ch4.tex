\chapter{Publishing LOD from a Spreadsheet}
\label{chap:proofOfConcept}

\begin{doublespace}

This Chapter provides a practical application of the methodology 
presented in Chapter~\ref{chap:methodology}
to describe and publish linked open data for a feedback survey.
The organization of this Chapter mirrors the preceding one,
as the methodology is applied to publish ~\ac{lod} from Hepting's feedback
survey.

\section{Describing Semantics for Survey Ontology}
\label{sec:describingsemanticsforsurvey}

As described in Chapter~\ref{chap:methodology}, 
to create a new ontology, 
an existing vocabulary can be reused or 
a new vocabulary can be described. 
According to the {\tt Linked Open Vocabularies} 
website\footnote{\tt https://lov.linkeddata.es/dataset/lov/vocabs?q=survey}, 
there are 6 survey-related vocabularies described, 
as shown in Figure~\ref{lov-website}. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/lov-website.png}
    \caption{Search Results for ``Survey'' on {\tt Linked Open Vocabularies}  Website}
    \label{lov-website}
\end{figure}

Some terms from the {\tt disco-DDI-RDF Discovery Vocabulary}~\cite{disco} 
can be reused to describe Dr. Hepting's student feedback form. 
For now, there is no existing vocabulary to describe ``likert'' items, 
so the vocabulary for {\tt Survey} ontology has been described 
without using any existing vocabularies. 
The following Section focuses on describing new vocabulary for {\tt Survey} ontology.

\subsection{Classes for Survey Ontology}
\label{subsec:surveyclasses}

All the classes can be created and 
described using the steps described in Section~\ref{subsubsec:classhierarchy}. 
The resultant class hierarchy for the survey ontology 
would be as shown in Figure~\ref{survey-class-hierarchy}. 
A {\tt Survey} can have 
{\tt Survey Collection}, 
{\tt Survey Respondent}, and 
{\tt Type of Survey} 
which have been considered for this ontology as well. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-class-hierarchy.png}
    \caption{Class Hierarchy in Survey Ontology}
    \label{survey-class-hierarchy}
\end{figure}

The {\tt SurveyCollection} class corresponds to a collection of survey responses 
that were collected for a particular course-offering ({\tt CourseOffering} class). 
The type of survey used is feedback survey ({\tt FeedbackSurvey} class, sub-class of {\tt Survey})
with Dr. Hepting's feedback survey 
as the specific survey instrument ({\tt HeptingStudentFeedbackSurvey} class)
and responses to the survey ({\tt HeptingStudentFeedbackSurveyRespondent} class). 

The survey questions and survey answers have classes 
corresponding to various forms of question-answer. 
Generally, 
feedback surveys consist of two types of questions, 
namely, 
\emph{Likert Questions} and \emph{Open-ended Questions}.
The type of questions might differ depending on the designer of the survey.
The feedback survey in this research has Likert and Open-ended questions. 
The classes described for the question and answer are 
{\tt SurveyQuestion} and {\tt SurveyAnswer} 
as sub-classes of 
{\tt HeptingStudentFeedbackSurvey} and 
{\tt HeptingStudentFeedbackSurveyRespondent} 
respectively.
For each survey question, 
there is an answer, 
where both of them are considered as distinct classes. 
The details of {\tt SurveyQuestion} and {\tt SurveyAnswer} classes 
are in following sections. 

\subsubsection{The ``SurveyQuestion'' Class}
\label{subsubsec:surveyqueclass}

Figure~\ref{survey-que-class} shows the {\tt SurveyQuestion} Class from survey ontology. 
Each question in survey has one question label whose datatype is string. 
It has two sub-classes, one for each of the 
{\tt OpenEndedQuestion} and {\tt LikertScaleQuestion} classes. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-que-class.png}
    \caption{{\tt SurveyQuestion} Class in Survey Ontology}
    \label{survey-que-class}
\end{figure}

The {\tt OpenEndedQuestion} class describes 
the set of 3 open-ended questions on the survey instrument 
where each question has it's own class (sub-class of {\tt OpenEndedQuestion}), 
namely, 
{\tt OEQ1}, {\tt OEQ2}, and {\tt OEQ3} 
with question labels, 
\emph{What do you like best about the course?}, 
\emph{What would you like to change about the course?}, and 
\emph{What do you think the instructor's greatest strengths are?} respectively. 

Likert-scale questions are the questions for which 
the answers are from the preset list of answers. 
The {\tt LikertScaleQuestion} class represents 
a set of 9 likert-scale questions from the survey instrument.
Each likert-scale question has a {\tt LikertQuestion} and a {\tt LikertScale}.  
where {\tt LikertQuestion} has the 9 questions each as a distinct class. 
{\tt LSQ1}, {\tt LSQ2}, . . , and {\tt LSQ9} are the classes 
with question label representing the question.

The {\tt LikertScale} class describes the likert scale used by Dr. Hepting in his survey. 
The likert scale has degrees of agreement-either in the form of label or a number, 
which determine the type of likert-scale used. 
Here, there are 5 options, 1, 2, 3, 4, and 5  
where 1 = Never and 5 = Always (see Figure~\ref{feedback-form}).
In the vocabulary, each of these degrees of agreement 
has been described as an individual of the {\tt LikertScale} class 
as shown in Figure~\ref{likert-scale-class}. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/likert-scale-class.png}
    \caption{{\tt LikertScale} Class in Survey Ontology}
    \label{likert-scale-class}
\end{figure}

\subsubsection{The ``SurveyAnswer'' Class}
\label{subsubsec:surveyansclass}

The {\tt SurveyAnswer} class respresents the responses to the questions of the survey. 
It has two sub-classes, one for each of the 
{\tt OpenEndedAnswer} and {\tt LikertScaleAnswer} classes.
The {\tt OpenEndedAnswer} class represents 
the set of answers for 3 open-ended questions.
Open-ended questions have unpredictable answers. 
Answer to each question is described by a disctinct class (sub-class of {\tt OpenEndedAnswer}) 
that consists of a string, 
namely, 
{\tt OEQ1Ans}, {\tt OEQ2Ans}, and {\tt OEQ3Ans}.
   
The {\tt LikertScaleAnswer} class represents 
the set of answers for 9 likert-scale questions. 
Answer to each question would be a value belonging to
the {\tt LikertScale},
which is between 1 and 5.
In case of no answer, the data field will be left blank. 
There are 9 sub-classes of the {\tt LikertScaleAnswer} class, 
namely, 
{LSQ1Ans}, {LSQ2Ans}, . . , and {LSQ9Ans}.
The next step is to describe properties.

\section{Data Validation Using SHACL}
\label{sec:shacl}

\ac{shacl}4P is a protégé plugin for \ac{shacl}, 
which uses \emph{shapes} to describe constraints. 
\ac{shacl} can be used to validate the manually entered data 
which are stored in spreadsheets. 
For feedback survey, 
the likert answers can only have values 
1, 2, 3, 4, 5, or No Answer (blank cell). 
To restrict the values of data properties 
corresponding to likert questions 
in Table~\ref{survey-data-properties-domains-and-ranges}, 
\ac{shacl}4P has been used. 

Protégé offers a view for \ac{shacl} editor as well as \ac{shacl} constraint violations. 
For successful working of \ac{shacl}4P, 
a reasoner should be enabled.

{\tt Open},

{\tt Validate}.

\section{Querying Survey Ontology in Protégé}
\label{sec:queryingontology}

The ontology vocabularies can be queried using query languages like 
DL query\footnote{https://protegewiki.stanford.edu/wiki/DL\_Query} 
and \ac{sparql}. 
Protégé offers a plugin for DL as well as SPARQL queries which are discussed in this section. 

\subsection{DL Query}
\label{subsec:dlquery}

Vasilevsky\footnote{https://ontology101tutorial.readthedocs.io/en/latest/EXERCISE\_BasicDL\_Queries.html} 
defines DL query as a class expression that is constructed using constructs such as 
{\tt and}, {\tt or} (corresponding to set intersection) and {\tt some}. 
Users can rapidly check that class definitions encompass the right subclasses 
by running them via the DL Query tab. 

Alternately, 
one can examine arbitrary descriptions 
for class membership without having to build 
placeholders for specified classes. 
The DL Query tab can be opened using Tabs option under Windows menu. 
It is important to configure a reasoner to successfully express a DL query.
Figure~\ref{survey-dl-query} 
shows expression of a sample DL query using the survey ontology in protégé. 

\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-dl-query.png}
    \caption{DL Query on Survey Ontology}
    \label{survey-dl-query}
\end{figure}

\subsection{SPARQL Query}
\label{subsec:sparql}

According to \ac{w3c}~\cite{garlik2013sparql}, 
\ac{sparql} queries use 
conjunctions, disjunctions, aggregation, subqueries, negation, and other operations 
to define queries and optional graph patterns. 
Protégé offers plugins for 
{\tt \ac{sparql} Query} and {\tt Snap \ac{sparql} Query}.

\subsubsection{Using \ac{sparql} Query Plugin}
\label{subsubsec:usingsparql}
    
\ac{sparql} plugin in protégé 
is used to express simple queries 
on ontologies like displaying classes and subclasses. 
For instance, 
consider the following query:

\begin{lstlisting}

    SELECT * WHERE { ?SurveyRespondent survey:hasOEQ1Ans 
    		?AnswerLikeBest
	OPTIONAL { ?SurveyRespondent survey:hasOEQ3Ans 
		?AnswerStrengths }
    }

\end{lstlisting}
       
 Figure~\ref{survey-sparql-query} 
 shows the result of expression of \ac{sparql} query on survey ontology. 
 Here, 
 the query is used to display 
 {\tt SurveyRespondent},  {\tt hasOEQ1Ans},  and {\tt hasOEQ3Ans} 
 with column titles SurveyRespondent, AnswerLikeBest and AnswerStrengths respectively.
    
\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-sparql-query.png}
    \caption{SPARQL Query on Survey Ontology}
    \label{survey-sparql-query}
\end{figure}
    
\subsubsection{Using Snap \ac{sparql} Query Plugin}
\label{subsubsec:usingsnapsparql}

The Snap \ac{sparql} plugin in protégé 
is generally used to express comparatively complex queries 
on ontologies 
like displaying description of individuals. 
For instance, 
consider the following query:    

\begin{lstlisting}

    SELECT * WHERE { ?Respondent rdf:type survey:SurveyRespondent .
	OPTIONAL {?Respondent survey:hasLSQ6Ans 
		?The_instructor_clearly_answers_questions}
    } ORDER BY ?SurveyRespondent 
   
\end{lstlisting}

Figure~\ref{survey-snap-sparql-query} 
shows the result of expression of Snap \ac{sparql} query on survey ontology. 
It is necessary to enable a reasoner for successful working of Snap \ac{sparql} query. 
Here, 
the query is used to display 
{\tt SurveyRespondent} and {\tt hasLSQ6Ans} 
with column titles ?Respondent and ?The\_instructor\_clearly\_answers\_questions respectively.
 
\begin{figure}[htp]
    \centering
    \includegraphics[width=\columnwidth]{images/ch4/survey/survey-snap-sparql-query.png}
    \caption{Snap SPARQL Query on Survey Ontology}

\section{Publishing Survey Vocabulary with License}
\label{sec:publishingsurveyvocabulary}

As mentioned in Section~\ref{sec:announcinglod}, 
it is necessary to specify an appropriate license for linked open data. 
When there is a clear declaration regarding 
the source, ownership, and conditions associated to 
the use of the public data, 
data reuse is more likely to happen.

\begin{itemize}
    
    \item Publishing Survey Vocabulary:
    
    The linked open vocabulary for feedback survey 
    that Dr. Hepting solicits from his students 
    in the classes he teaches, 
    can be accessed as \ac{turtle} 
    file from my website\footnote{\tt https://parita-amin.github.io/sample.ttl} 
    or can be viewed by visiting the link to the \ac{turtle} 
    file on my website\footnote{\tt https://parita-amin.github.io/evaluationofteaching.html} 
    (see Figure~\ref{survey-license}).
    
    \begin{figure}[htp]
       \centering
       \includegraphics[width=\columnwidth]{images/ch4/survey/survey-license.png}
       \caption{Link to Turtle File containing Survey Vocabulary}
       \label{survey-license}
    \end{figure}       
   
    \item License:
    
    The linked open dataset discussed in this research has an 
    {\tt Attribution-ShareAlike 4.0 International}\footnote{\tt https://creativecommons.org/licenses/by-sa/4.0/}
    open license. 
    The degree of transparency increases as more data become available under an open license. 
    This makes it possible for the user to investigate the relationships in the data and use it effectively. 

\end{itemize}
